# 业务价值与产品说明

## 1. 产品定位

AgentShelf 是跨境商品发布前的 AI 质量与安全检查平台。它位于商品资料系统和销售平台之间，把商品资料整理、Listing 生成、规则检查、Agent 红队测试、修复复测和人工确认连接起来。

产品只聚焦“AI 智能上新”一个命题。协议适配和模拟结账不是另一个命题，而是用于验证上新后的商品能否被购物 Agent 安全读取和使用。

## 2. 目标用户

| 用户 | 日常任务 | 主要困难 | AgentShelf 提供的价值 |
| --- | --- | --- | --- |
| 跨境卖家运营 | 整理资料、生成内容、多平台发布 | 资料散、规则多、重复核对 | 统一资料源，一次配置生成多平台内容和检查结果 |
| 商品与合规人员 | 核对卖点、认证、政策和市场限制 | 很难追踪文案来自哪份资料 | 卖点来源台账、冲突与未知项、版本差异 |
| 电商 ISV | 为多个卖家提供上新和发布服务 | 需要可复用的质量与安全能力 | API、规则引擎、任务库、故障库和报告输出 |
| 平台运营与治理人员 | 降低错误商品信息和 Agent 交易风险 | 传统审核难覆盖机器读取内容 | Agent 红队任务、实时状态核对和确认式结账 |

## 3. 用户当前流程与问题

典型流程是：收集资料、人工整理、使用翻译或文案工具、逐个平台填写、人工检查、提交后再根据错误返工。问题集中在四处：

1. **输入不统一**：表格、图片和政策没有统一结构，冲突经常被忽略。
2. **生成不可追溯**：文案看起来合理，但无法快速说明材料、尺寸、认证或承诺来自哪里。
3. **检查不完整**：内容检查与价格、库存、运费和配送检查互相分离。
4. **发布后才发现风险**：缺少面向购物 Agent 的测试，评论注入或状态差异可能进入后续交易。

## 4. AgentShelf 的业务流程

1. 运营人员导入商品 CSV、图片和政策资料。
2. 系统生成 Product Passport，标记来源、冲突和未知项。
3. 运营人员选择销售平台、目标市场、语言和品类。
4. 系统生成本地化 Listing，并执行平台发布前检查。
5. 系统运行 30 个买家任务和选定的受控故障。
6. 若发现问题，系统阻止模拟交易并生成修复版本。
7. 使用相同任务和故障复测，确认问题是否真正解决。
8. 运营人员再次核对内容、价格、库存和配送状态。
9. 系统导出发布文件和完整测试证据。

## 5. 价值对应关系

| 业务问题 | 产品能力 | 可观察结果 |
| --- | --- | --- |
| 资料整理耗时 | CSV、图片、政策统一生成 Product Passport | 每个 SKU 形成统一且可版本化的商品资料 |
| 卖点缺少来源 | Listing 卖点与可信事实 ID 绑定 | 可统计有来源卖点的比例 |
| 多平台规则复杂 | 按平台、市场和语言执行差异规则 | 每次生成都有结构化检查结果 |
| 实时状态不一致 | 发布和模拟结账前核对价格、库存、运费和版本 | 状态变化时阻止继续操作 |
| Agent 输入风险 | 30 个任务和 12 个受控故障 | 问题可以重现、定位和分类 |
| 修复缺少证据 | 新版本、结构化差异、同任务复测 | 可以比较修复前后的结果 |
| 自动化责任不清 | 强制人工确认 | 保存确认内容和批准记录 |

## 6. 核心差异

### 与普通 Listing 生成工具相比

普通工具的输出重点是文案，AgentShelf 的输出还包括商品事实、来源、平台检查、红队测试、修复记录和发布确认。模型不可以自由添加无法验证的卖点。

### 与传统内容审核相比

传统审核主要检查文本是否违规。AgentShelf 同时检查购物 Agent 会读取的商品字段、评论、OCR、实时商业状态和工具调用过程，并验证从搜索到模拟结账的完整路径。

### 与单次测试脚本相比

单次脚本只能说明某次运行结果。AgentShelf 保存任务、故障、输入版本、运行轨迹、评分、修复版本和复测结果，可以形成持续使用的发布前测试基线。

## 7. 建议业务指标

### 效率指标

- 单个 SKU 的资料整理时间。
- 从导入资料到形成可审核 Listing 的时间。
- 每个问题的平均定位和修复时间。
- 同一商品适配多个平台和市场的重复工作量。

### 质量指标

- 有可信来源的 Listing 卖点比例。
- 首次平台检查通过率。
- 红队测试发现的问题数和严重程度。
- 修复后同任务通过率。
- 发布后因内容、事实或商业状态问题产生的返工次数。

### 系统指标

- Product Passport 结构校验通过率。
- Qwen 调用成功率、平均时延和单 SKU 成本。
- 商业 API 状态核对成功率。
- 人工确认前被系统阻止的高风险操作数。

## 8. 预期效果与验证方法

以下均为待真实业务验证的产品目标，不是当前已取得的经营数据：

| 预期效果 | 验证方法 |
| --- | --- |
| 缩短上新准备时间 | 选择一组真实 SKU，对比原流程和 AgentShelf 流程的用时 |
| 提高卖点可追溯性 | 统计最终 Listing 中有明确来源的卖点比例 |
| 提前发现跨境风险 | 记录发布前发现的问题类型、严重程度和后续是否避免返工 |
| 降低重复复测成本 | 比较人工复测与自动同任务复测的用时和一致性 |
| 提高 Agent 交易安全 | 统计注入、金额、库存、配送和事实冲突场景的阻止率 |

建议试点选择 20–50 个真实 SKU，覆盖两个市场和两个平台，运行 2–4 周。试点前确定基准流程，试点期间保存每个 SKU 的用时、问题和人工操作，才能形成可信的业务价值结论。

## 9. 商业化方向

### 面向卖家团队

按组织、SKU 数量或月度上新量订阅，提供商品资料整理、平台检查、红队测试和报告导出。

### 面向电商 ISV

提供 API 和嵌入式工作台，让现有 PIM、ERP、Listing 管理和发布产品增加 Product Passport、规则检查和 Agent 测试能力。

### 面向平台和生态治理

提供规则包、风险任务库和发布前质量报告，帮助平台或服务商建立面向购物 Agent 的商品质量基线。

商业模式需要在真实试点中验证。比赛阶段的重点是证明问题成立、流程可运行、技术边界可信，而不是提前承诺收入规模。

## 10. 产品路线

### 当前：可运行比赛原型

- 完整前端工作台。
- Qwen 与固定规则协作。
- 30 个任务、12 个故障、5 个商业沙箱 API。
- 修复复测、人工确认和文件导出。

### 下一步：小规模卖家试点

- 真实商品资料和平台规则导入。
- 账号、组织、权限和持久化。
- 一个平台测试环境连接器。
- 业务和模型指标面板。

### 后续：生产级服务

- 多租户和完整审计。
- 更多品类、平台、市场和语言。
- 规则版本中心和平台连接器市场。
- 与卖家 PIM、ERP 和发布系统双向同步。
