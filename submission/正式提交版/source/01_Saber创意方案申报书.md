## 二、方案名称

**AgentShelf：面向 AI 购物 Agent 的跨境商品安全上新平台**

## 三、方案简介

AgentShelf 面向跨境卖家、电商运营团队和电商 ISV，将分散的商品表格、图片、认证与政策资料整理为可追溯的 Product Passport，再生成适配平台、市场和语言的本地化 Listing。发布前，系统会检查内容、价格、库存、配送和平台规则，并通过 Agent 红队测试发现指令注入、事实冲突和交易状态异常。问题修复后，系统使用相同条件复测，最后由运营人员确认并导出发布文件。

## 四、业务问题

跨境商品上新需要同时处理商品事实、平台规范、语言表达、市场政策和实时商业状态。现有工具通常侧重文案生成，仍存在以下问题：

1. 商品资料分散，人工整理速度慢，冲突和缺项容易被忽略。
2. Listing 中的卖点、认证和承诺缺少来源，难以审核。
3. 页面内容可能与当前价格、库存、运费和配送范围不一致。
4. 评论、隐藏文本和图片 OCR 可能误导购物 Agent。
5. 问题发现后缺少固定输入、修复版本和同条件复测证据。

## 五、目标用户

- 需要多平台、多国家上新的跨境卖家和运营团队。
- 为卖家提供商品管理、内容生成和发布服务的电商 ISV。
- 负责商品质量、合规和平台生态治理的运营人员。

## 六、核心方案

### 1. 商品档案整理

导入 CSV、商品图片和政策资料，生成带来源、版本、冲突和未知项的 Product Passport，建立统一商品事实来源。

### 2. 本地化 Listing 生成

根据销售平台、目标市场、语言和品类生成标题、卖点、描述与 Search Terms。每条可发布表述均绑定可信事实来源。

### 3. 发布前检查

检查必填字段、内容长度、语言与市场、卖点来源、风险表述、价格、库存、运费和配送状态，给出清晰的通过或阻止结果。

### 4. Agent 红队测试与修复

系统内置 30 个买家任务和 12 个受控故障，覆盖指令注入、商业状态、商品事实和跨境政策。发现问题后生成新版本，并使用相同任务和故障复测。

### 5. 人工确认与文件导出

运营人员核对内容与实时商业状态后，系统生成 Listing、平台导入表、Product Feed、Schema.org JSON-LD、UCP Manifest 和测试报告。

## 七、技术路线

前端使用 Next.js、React 和 TypeScript 构建操作台；服务端使用 Next.js Route Handlers 提供商品资料整理、Listing 生成、语义复核和商业沙箱能力；Zod 负责结构校验，Papa Parse 负责 CSV 解析。

Qwen 用于理解图片与政策资料、优化 Listing 结构并复核复杂语义。金额、库存、配送、版本和放行条件由固定规则处理。模型只输出结构化建议，不能直接改写原始事实或触发真实支付。

## 八、创新点

1. 从“生成文案”扩展为“生成、检查、测试、修复、复测、确认”的完整上新流程。
2. 以 Product Passport 统一商品事实，让 Listing、测试和导出文件引用同一版本。
3. 同时验证用户可见内容与购物 Agent 可读取的评论、OCR、结构化字段和工具结果。
4. 修复前后使用同一任务和故障，结果可比较、可追溯。
5. 通过签名购物车、状态复核和显式确认验证交易安全，全程不产生真实扣款。

## 九、预期业务价值

- 减少商品资料整理和多平台重复录入工作。
- 提高 Listing 卖点的来源完整度和审核效率。
- 在发布前发现价格、库存、配送、政策和内容冲突。
- 缩短问题定位、修复和复测时间。
- 为 AI 购物场景建立可扩展的商品质量与交易安全基线。

## 十、已实现成果

AgentShelf 已实现可运行 Web 操作台、Product Passport、三类平台 Listing、30 个买家任务、12 个受控故障、修复复测、人工确认、5 个商业沙箱 API 和多种发布文件导出。核心逻辑具备自动测试，主要流程具备浏览器端到端验证。
