# 提交检查清单

## 1. 官方表单

- [ ] 团队名称已填写，和报名信息一致。
- [ ] 队长姓名、电话和邮箱已填写并复核。
- [ ] 参赛场景选择“AI 智能上新”。
- [ ] 方案名称使用最终版本。
- [ ] 方案概述说明了具体问题、目标用户和业务痛点。
- [ ] 核心功能控制在 3–5 项，本方案使用 5 项。
- [ ] 方案亮点和预期效果分开表述。
- [ ] 技术方案说明模型、Agent/工作流、数据处理、前后端和其他技术组件。
- [ ] 没有把计划功能写成已实现功能。

## 2. 附加材料

- [ ] 上传技术方案或提供可访问链接。
- [ ] 上传系统架构图和完整工作流图。
- [ ] 上传 5–10 张清晰的关键页面截图。
- [ ] 提供 5 分钟左右的演示视频链接。
- [ ] 提供代码仓库地址；若不公开，确认评委的访问方式。
- [ ] 提供公开原型地址，或清楚写出本地运行方法。
- [ ] 所有附件中的方案名称、团队名称、数量和技术表述一致。

## 3. 产品演示

- [ ] “方案总览”能在 30 秒内说明问题、用户、流程和 AI 分工。
- [ ] 商品档案可以载入 CSV、政策和图片示例。
- [ ] 可以生成 Product Passport，并看到来源、冲突或未知项说明。
- [ ] 可以切换平台和市场，生成对应的 Listing。
- [ ] 可以展示卖点来源和发布前检查结果。
- [ ] 可以运行红队测试并出现一次“交易已阻止”。
- [ ] 可以生成修复版本并使用同一场景复测通过。
- [ ] 可以完成两项人工确认并看到发布文件。
- [ ] 协议适配可以运行 5 个商业 API，结账保持不扣款。
- [ ] 桌面和手机界面没有横向溢出、文字遮挡或空白区域。

## 4. 技术验证

- [ ] `npm run lint` 通过。
- [ ] `npm test` 的 30 个单元测试通过。
- [ ] `npm run build` 通过。
- [ ] `npm run test:e2e` 的 9 个端到端场景通过。
- [ ] 在没有 Qwen API Key 时，固定规则流程仍可演示。
- [ ] 在配置 Qwen API Key 时，模型状态和调用正常。
- [ ] 下载文件的名称、内容和数量与界面一致。
- [ ] 截图与视频中的数量和测试报告一致。

## 5. 安全与隐私

- [ ] `.env.local` 未提交到代码仓库。
- [ ] 源码、提交记录、截图和视频中没有 API Key、令牌或真实密钥。
- [ ] 演示商品不包含未经授权的个人数据或商业机密。
- [ ] 商品图片、字体和其他素材具有可使用的来源或授权。
- [ ] 视频没有录入个人聊天、浏览器书签、邮箱、手机号等无关信息。
- [ ] 文案明确写“模拟结账”“不触发真实支付”。
- [ ] 文案没有宣称获得 Amazon、Shopify、TikTok Shop、UCP、ACP、MCP 官方认证。

## 6. 内容一致性

- [ ] 全部页面优先使用清晰中文，专业名词保留英文。
- [ ] `Agent`、`Product Passport`、`Listing`、`Feed`、`API`、`UCP`、`ACP`、`MCP` 拼写统一。
- [ ] “30 个买家任务、12 个受控故障、5 个商业 API、3 种协议映射”在所有材料中一致。
- [ ] “三个平台、两个市场”与当前原型一致。
- [ ] 当前能力写“已实现”，真实平台、生产部署和 ROI 写“下一步”或“待验证”。
- [ ] 没有难懂的内部表达，例如把“整理商品档案”写成“契约编译”，把“修复并复测”写成“回归闸门”。

## 7. 提交前最后一次操作

1. 清理浏览器无关标签页并重启前端。
2. 按演示脚本完整运行一遍，确认界面、模型、下载和截图正常。
3. 运行全部自动测试并把结果更新到测试报告。
4. 检查公开演示地址、仓库地址和视频链接能在未登录环境打开。
5. 使用另一台设备或无痕窗口打开全部链接。
6. 将最终提交内容导出或截图留档，记录提交时间。
